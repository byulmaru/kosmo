# 첫 Profile 온보딩 정책

## 목적과 권위

[PROD-1146](https://linear.app/byulmaru/issue/PROD-1146)은 인증을 마친 뒤 Profile이 없는 사람이 첫 소셜
정체성을 준비하는 경험을 소유한다. 이 문서는 사용자가 검토한 다섯 화면과 첫 단계에서 생성한 Profile의
선택 정보를 단계별로 저장하는 흐름을 반영한다. 화면 구성과 한국어 문구는
[첫 프로필 온보딩 디자인](../../design/first-profile-onboarding.md)이 소유한다. Profile 생성·편집 자격과
값 검증은 [Profile](../objects/profile.md)의 기존 계약을 따른다.

## 대상과 진입

- 유효한 인증 상태에서 코스모 Profile이 0개인 사람에게 제공한다. 별마루 ID 신규 가입과 기존 계정 로그인을
  구분해 일부를 제외하지 않는다.
- 현재 인증 상태와 Profile 보유 여부를 확인하지 못한 동안에는 입력 화면을 확정하지 않는다. 조회 실패를
  비로그인 또는 Profile 0개로 간주하지 않는다.
- 이미 Profile이 있는 사람의 새 진입은 기존 선택·사용 흐름을 따른다. 첫 Profile을 생성한 뒤 온보딩을
  떠났다가 다시 들어와도 온보딩을 처음부터 시작하거나 이전 단계를 재개하지 않는다.
- 진행 중인 첫 Profile 온보딩에서는 첫 단계에서 생성한 Profile을 유지한다. 생성으로 Profile 보유 여부가
  바뀌었다는 이유만으로 진행 중인 선택 단계를 닫지 않는다.

## 입력과 이동

- 핸들, 사진·표시 이름·소개, Profile Tag, 게시 설정, 확인 순서로 진행한다. 기존 프로필 수정 화면 전체를
  가입 온보딩으로 전용하지 않는다.
- 핸들은 필수다. 빈 값, 잘못된 형식, 예약 식별자와 이미 사용 중인 핸들로 생성할 수 없다. 기존 Local handle
  검증과 서버의 최종 유일성 판정을 유지한다.
- 첫 핸들 화면의 `다음`은 첫 Profile을 생성·선택한 뒤 사진·표시 이름·소개 단계로 이동한다. 같은 화면의
  `바로 시작`도 첫 Profile을 생성·선택하지만 선택 단계를 모두 생략하고 완료한다. 두 번째 화면을 거쳐야
  하는 추가 조건이나 핸들 단계를 건너뛰는 action은 만들지 않는다.
- 사진·헤더 이미지·표시 이름·소개·Profile Tag는 선택 사항이다. 생성 시 표시 이름은 핸들을 사용하고,
  소개는 빈 값으로, 사진과 Tag는 관계 없이 시작할 수 있다.
- 게시 설정의 초기값은 기본 공개 범위 Unlisted와 Follow Approval Policy Open이다.
- 2~4단계의 `다음`은 현재 단계의 선택 정보를 같은 Profile에 저장한 뒤 다음 단계로 이동한다. 이전 단계나
  다른 단계의 미저장 입력을 함께 저장하지 않는다.
- `지금은 건너뛰기`는 현재 단계의 미저장 입력을 저장하지 않고 다음 단계로 이동한다. 2~4단계의 `바로 시작`은
  현재 단계와 남은 선택 단계를 저장 없이 생략하고 완료한다. 이미 저장한 값은 유지한다.
- 모든 온보딩 단계에 이전 단계로 돌아가는 action을 제공하지 않는다. 지난 단계의 정보는
  온보딩 완료 후 기존 프로필 편집·설정에서 수정한다.
- 확인 화면은 저장된 Profile을 요약한다. `다음`은 사람 찾기 또는 홈으로 이어지며, 새로운 Profile을 생성하거나
  미저장 선택 정보를 한꺼번에 저장하지 않는다.
- `프로필은 나중에 만들기`처럼 Profile을 0개로 남기는 전체 온보딩 스킵은 이번 흐름에 제공하지 않는다.
  공개 콘텐츠의 기존 읽기 권한은 별도로 유지한다.

## 생성과 완료

- 첫 핸들 단계에서 첫 Local Profile 하나와 Owner Membership을 준비하고, 생성한 Profile을 현재 활동
  Profile로 선택한다. 선택 단계의 진행·생략과 확인·완료는 추가 생성 action이 아니다.
- 프로필 입력 뒤 실제 저장 태그가 있으면 사람 찾기로 이어지고, 태그가 없으면 이를 생략한다. 사람 찾기의 `계속하기`로 홈에 진입한다. 별도의 프로필 완료 화면은 표시하지 않는다.
- 진행 중인 같은 흐름에서는 생성한 Profile과 그 식별자를 유지한다. 생성 전의 Profile 0개 상태로
  되돌리거나 새 Profile을 추가로 만들지 않는다. 완료 후 입력 단계로 복귀하는 별도 동선은 제공하지 않는다.
- 선택 단계의 저장은 같은 Profile의 사진·헤더 이미지·표시 이름·소개·Tag·게시 설정에 적용한다. Profile 편집과
  기본 공개 범위 변경의 기존 자격을 다시 확인한다. 다른 Profile로 대상이 바뀌면 이전 대상의 입력이나 늦은
  저장 결과를 새 대상에 적용하지 않는다.
- 핸들 변경은 기존 PROD-1146의 제외 범위를 유지하며, 생성한 핸들은 이 흐름에서 변경하지 않는다.
- 생략·완료는 선택 정보를 저장하지 않으며, 이미 저장한 값을 취소하거나 삭제하지 않는다. 선택 정보를
  저장하는 action은 해당 단계의 `다음`이다.
- 브라우저·시스템 뒤로가기는 기존 플랫폼 동작을 따르며, 온보딩을 위해 별도의 차단이나 복귀 처리를 추가하지 않는다.
- 직접 가입에서 준비한 Profile과 저장한 Tag는 후속 온보딩이 사용할 수 있다. 이 흐름이 사람 추천, 팔로우
  또는 후속 Coachmark를 자동 실행하지는 않는다.

## 검증과 실패

- 핸들, 표시 이름, 소개, Tag와 이미지의 기존 검증을 적용한다. 잘못된 입력이나 준비되지 않은 이미지를
  저장 성공으로 처리하지 않는다.
- 생성·저장 중에는 같은 요청을 중복 실행하지 않는다. 처리 중 입력과 이동은 중복 저장이나 대상 혼동을
  만들지 않게 보호하고, 실패 후에는 입력을 유지한 채 재시도할 수 있어야 한다.
- 첫 Profile의 생성·선택을 확인하지 못했으면 다음 단계나 완료로 안내하지 않는다. 오류는 관련 항목 또는
  action 가까이에 표시한다.
- 선택 정보 저장에 실패하면 해당 오류를 안내하고 같은 Profile과 입력을 유지한다. `다음`으로 재시도하거나
  `지금은 건너뛰기`·`바로 시작`으로 미저장 선택 정보를 생략할 수 있다. 선택 정보의 검증·이미지 처리·저장
  실패가 이미 생성한 Profile의 사용을 막지는 않는다.
- 확인 요약에는 저장된 실제 값을 사용한다. 생략한 입력이나 실패한 저장을 반영된 값으로 안내하지 않는다.
- 현재 단계의 검증·저장 실패 후에는 입력 초안을 유지한다. 세션이나 기기를 넘는 장기 초안 저장, 흐름 이탈
  뒤의 온보딩 재개는 제공하지 않는다. 재진입 시에는 현재 Profile 보유 여부에 따른 일반 흐름을 따른다.

## 범위와 관계

- [공개 콘텐츠 방문자 온보딩](./public-content-onboarding.md)과 PROD-836의 공개 읽기·인증 진입은 유지한다.
  공개 콘텐츠에서 시작한 인증 뒤 원래 콘텐츠로 자동 복귀하는 기능은 이번 범위에 넣지 않는다.
- 기존 프로필 편집·설정·추가 생성·전환과 핸들 변경을 재설계하지 않는다. 첫 Profile 온보딩의 입력 경험만
  기존 계약을 활용한다.
- 공용 Coachmark는 PROD-678, 생성 이후 사람 찾기는 PROD-1147, 홈과 핵심 기능 안내는 PROD-1148,
  모바일 마지막 알림 단계는 PROD-1149가 소유한다. 이 문서는 해당 후속 경험의 동작을 추가하지 않는다.
- 게시물 해시태그·해시태그 목록, 추천 Tag·인물·관심사, 인증 수단 추가와 공개 범위 정책 변경은 포함하지 않는다.

## 완료 결과

1. Profile이 없던 Account가 첫 핸들 단계의 `다음`으로 첫 Profile을 생성·선택한 뒤 선택 정보를 입력할 수 있다.
2. 유효한 핸들만 입력한 첫 화면에서도 한 번의 `바로 시작`로 생성·선택하고 완료할 수 있다.
3. 각 선택 단계의 `다음`은 해당 단계만 저장하며, `지금은 건너뛰기`와 `바로 시작`은 미저장 입력을 저장하지
   않고 진행·완료한다.
4. 모든 온보딩 단계에서 이전 단계로 돌아가는 action을 제공하지 않는다. 지난 정보의 수정은 완료 후
   기존 프로필 편집·설정에서 하며, 확인에서 전체 정보를 다시 저장하지 않는다.
5. 선택 정보의 검증·이미지 처리·저장 실패를 안내하고 재시도·생략·완료할 수 있다. 생성한 Profile과 이미
   저장한 정보는 유지한다.
6. 흐름을 떠난 뒤 재진입한 Profile 보유자는 기존 선택·사용 흐름으로 이어지고, 기존 Profile 편집·선택과
   공개 콘텐츠 읽기를 유지한다.
