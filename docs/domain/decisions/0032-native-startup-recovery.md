# ADR 0032: Native 앱 복귀 시 실패한 조회 복구

## 상태

Accepted

## 날짜

2026-10-22, 2026-11-16 개정

## 맥락

앱 초기 로딩 중 화면을 잠갔다가 돌아오면 일시적인 연결 끊김 뒤 앱 전체나 홈의 오류 화면에 머무를 수 있다.
화면 잠금·복귀는 로그아웃이나 프로필 선택 해제의 근거가 아니다.

## 결정

- iOS와 Android Native 앱은 백그라운드에서 복귀할 때 실패 상태인 조회를 기존 재시도 경로로 다시 실행한다.
  초기 로딩 여부나 잠금이 실패 원인인지, 이전 자동 재시도 횟수는 복구 조건으로 삼지 않는다.
- 재시도도 실패하면 기존 오류 안내와 수동 재시도를 유지하고 다음 복귀 때 다시 시도할 수 있다.
  복귀 이벤트 없이 연결이 돌아올 때까지 자동 시도를 반복하지 않는다.
- 성공했거나 진행 중인 조회와 사용자 변경 작업은 이 정책으로 자동 재실행하지 않는다.
- 일시적인 연결 실패만으로 유효한 Session credential이나 클라이언트가 기억하는 selected Profile을 제거하지 않는다.
  먼저 시작한 조회의 늦은 결과가 더 최근의 Account나 Profile 선택을 덮어쓰지 않도록 한다.
- 조회별 재시도는 무관한 화면·내비게이션·다른 Profile의 데이터를 초기화하지 않는다.
  루트까지 전파된 오류는 기존 앱 전체 재시도 경로를 따르며, 서버가 확인한 인증 만료·guest 전환은 기존 계약을 따른다.

## 이유

조회 오류를 기존 복구 경계에서 재시도하면 잠금 원인이나 초기 로딩 완료 여부를 별도로 추적하지 않고 이용을
이어갈 수 있다. 지속적인 오류에서는 기존 안내를 유지하고 사용자의 다음 복귀 또는 수동 입력을 기다린다.

## 범위

이 결정은 Native 앱의 실패한 조회 복구에 적용한다. Web, 사용자 변경 작업의 자동 재실행,
기기 재부팅·프로세스 종료 후 복원은 범위에 포함하지 않는다. 성공한 Home의 기존 생명주기 갱신 정책은 유지한다.
iOS와 Android의 잠금·복귀 결과는 각각 검증하며, 한 플랫폼의 비재현을 전체 플랫폼의 영향 없음으로 해석하지 않는다.
