# 첫 프로필 온보딩

## 범위와 기준

제품 동작은 [첫 Profile 온보딩 정책](../domain/policies/first-profile-onboarding.md)과
[PROD-1146](https://linear.app/byulmaru/issue/PROD-1146)을 따른다. 이 문서는 검토한 시안의 화면 순서와
문구에 첫 단계 생성·선택, 선택 정보의 단계별 저장·생략 흐름을 반영한다.

기존 프로필 수정 화면 전체를 재사용하지 않고 한 단계씩 진행한다. 사진·입력·Tag·게시 설정의 공용 control과
기존 검증·접근성 표현은 활용한다. 신규 기능 소개를 위한 긴 설명이나 별도 학습 단계를 추가하지 않는다.

## 화면 순서와 공통 구성

`핸들 → 사진·표시 이름·소개 → 프로필 태그 → 게시 설정 → 확인`

- 상단에 KOSMO 로고와 현재 진행 단계를 표시한다. 모든 단계와 완료 화면에 이전 화면 action을 제공하지 않는다.
- 1~4단계의 우상단 action 문구는 모두 `나중에 설정`이다. 첫 화면에서도 유효한 핸들을 입력하면 바로 사용할 수 있다.
- 1~4단계의 주 action은 `다음`이다. 2~4단계 하단에는 `지금은 건너뛰기`를 제공한다. 첫 화면에는 단계 건너뛰기를
  제공하지 않으며 빈 핸들로 `다음`이나 `나중에 설정`을 실행할 수 없다.
- 첫 단계의 `다음`은 Profile을 생성·선택한 뒤 다음 단계로 이동한다. 첫 단계의 `나중에 설정`은 같은 생성·선택을
  거쳐 선택 단계를 모두 생략하고 완료한다.
- 2~4단계의 `다음`은 현재 단계만 저장하고 이동한다. `지금은 건너뛰기`는 현재 단계의 미저장 입력을 저장하지
  않고 이동하며, `나중에 설정`은 현재 단계와 남은 선택 단계를 저장 없이 생략하고 완료한다.
- 확인 화면의 action은 `다음`이다. 프로필 입력 뒤 실제 저장 태그가 있으면 사람 찾기로 이어지고, 태그가 없으면 이를 생략한다. 사람 찾기 뒤 최종 완료 화면에서만 `시작하기`로 홈에 진입한다. 미저장 정보를 일괄 저장하지 않는다.
- 미저장 입력과 실제로 저장된 값을 구분한다. 지난 단계의 정보를 바꾸려면 온보딩을 완료한 뒤 기존 프로필
  편집·설정을 이용한다.
- 서버 오류가 없는 초기 입력은 비워 둔다. 시안의 `bom`, `봄`, 예시 소개나 Tag를 실제 입력값으로 채우지 않는다.
- `첫 프로필 · …` 또는 `첫 프로필: …` 같은 보조 제목은 표시하지 않는다. 화면 제목으로 현재 할 일을 전달한다.

## 1. 핸들

| 요소          | 문구 또는 표현                                                                |
| ------------- | ----------------------------------------------------------------------------- |
| 제목          | 나만의 핸들을<br>정해 주세요                                                  |
| 설명          | 코스모에서 내 프로필을 찾을 때 사용하는 아이디예요.                           |
| 필드          | 핸들                                                                          |
| 입력 표현     | 앞에 장식용 `@`를 표시한다. 자동 대문자 입력과 맞춤법 검사를 사용하지 않는다. |
| placeholder   | 예: bom                                                                       |
| 주소 미리보기 | 내 프로필 주소: `{현재 서비스 도메인}/@{핸들}`                                |

주소는 실제 서비스 도메인과 입력값으로 표시한다. `아이디와 닉네임은 어떻게 다른가요?`, 로그인 이메일과의
비교, 여러 문단의 핸들 설명과 `알아보기` action은 추가하지 않는다. 기존 3~30자 영문·숫자·밑줄, 예약 식별자와
유일성 검증을 사용하며 필드 가까이에 오류를 표시한다.

`다음`이나 `나중에 설정`으로 생성·선택 중인 상태를 표시하고 중복 실행을 막는다. 생성·선택이 실패하면
입력을 유지하고 오류를 표시한다.

생성한 핸들은 이 흐름에서 변경하지 않는다. 생성 후 선택을 재시도할 때도 같은 Profile을 유지한다.

## 2. 사진·표시 이름·소개

| 요소             | 문구 또는 표현                                      |
| ---------------- | --------------------------------------------------- |
| 제목             | 나를 소개하는<br>프로필을 꾸며 보세요               |
| 설명             | 프로필 사진과 표시될 이름, 짧은 소개를 넣어 주세요. |
| 이름 label       | 표시 이름                                           |
| 이름 설명        | 다른 사람들에게 보이는 닉네임이에요.                |
| 이름 placeholder | 사람들에게 보일 이름                                |
| 소개 label       | 소개                                                |
| 소개 설명        | 당신이 어떤 사람인지 알려주세요.                    |
| 소개 placeholder | 예: 책과 애니메이션 이야기를 좋아해요.              |

사진은 헤더 이미지와 프로필 사진을 선택할 수 있게 한다. 헤더 비율과 avatar overlap, 선택·교체·제거·업로드와
오류 표현은 [프로필 편집](./profile-edit.md)과 [이미지 업로드 오류 안내](./media-upload-errors.md)를 따른다.
온보딩을 위한 새 crop·pan·zoom 기능을 추가하지 않는다.

표시 이름은 입력하면 Unicode code point 기준 40자 이내이며, 입력하지 않으면 핸들로 시작한다. 소개는 앞뒤 공백을
제거한 뒤 500자 이하다. 두 필드의 글자 수를 표시한다. `사진과 소개는 나중에 추가해도 괜찮아요.`나 별도의
`사진·닉네임·소개 알아보기` 링크는 표시하지 않는다.

## 3. 프로필 태그

| 요소        | 문구 또는 표현                                                                    |
| ----------- | --------------------------------------------------------------------------------- |
| 제목        | 어떤 것들을<br>좋아하나요?                                                        |
| 설명        | 당신의 취향을 프로필에 태그로 남겨 보세요.                                        |
| 필드 label  | 프로필 태그                                                                       |
| 필드 설명   | 태그를 달면 내 프로필에 표시돼요. 취향이 맞는 사람들과 교류할 기회를 늘려 보세요. |
| placeholder | 예: 애니메이션                                                                    |
| 추가 action | 추가                                                                              |

추가한 Tag는 제거할 수 있는 chip으로 표시하고, Tag 없이 다음으로 진행할 수 있다. 정규화·중복·허용 문자·길이·
개수·순서는 [Profile Tag 디자인](./profile-tags.md)과 기존 Hashtag Name 계약을 따른다. 시안의 단순 정규화를
기존 검증 대신 사용하지 않는다.

`태그 없이도 다음으로 갈 수 있어요.`, `태그로 사람을 찾는 방법`, 추천 관심사 묶음·추천 Tag와 자동완성을
추가하지 않는다. Twitter 참고 화면의 추천 항목과 인물은 코스모의 기능으로 옮기지 않는다.

## 4. 게시 설정

| 요소            | 문구 또는 표현                                                                                     |
| --------------- | -------------------------------------------------------------------------------------------------- |
| 제목            | 게시 설정                                                                                          |
| 설명            | 게시물의 공개 범위와 팔로우 요청 방식을 정해 주세요.                                               |
| 공개 범위 label | 게시물 기본 공개 범위                                                                              |
| 공개 범위 설명  | 내 작성글이 노출되는 기본 범위를 정할 수 있어요. 게시글을 작성할 때 개별적으로 변경할 수도 있어요. |
| 자동 승인 label | 팔로우 요청 자동 승인                                                                              |
| 자동 승인 설명  | 설정을 끄면 팔로우 요청을 확인하고 원하는 사람만 수락할 수 있어요.                                 |

공개 범위는 한 항목만 선택할 수 있는 목록으로 표시하고, 각 항목의 설명을 함께 보여 비교할 수 있게 한다.

| 선택지      | 설명                                 |
| ----------- | ------------------------------------ |
| 전체 공개   | 누구나 볼 수 있어요.                 |
| 조용한 공개 | 누구나 볼 수 있지만 검색되지 않아요. |
| 팔로워만    | 나를 팔로우하는 사람만 볼 수 있어요. |

기본 선택은 `조용한 공개`, 자동 승인 Switch는 켜짐이다. 자동 승인 설명은 켜짐 여부와 관계없이 위 문구를
사용한다. 게시물 해시태그 목록이나 멘션 대상자의 별도 열람 권한을 설명에 끼워 넣지 않는다.

기본 공개 범위 변경과 자동 승인 변경의 실제 효과는 [Profile 정책](../domain/objects/profile.md)을 따른다.
이미 작성한 글과 열려 있는 Composer의 공개 범위, 기존 Pending Follow Request는 바꾸지 않는다.
기존 프로필 설정 화면의 소유권과 자동 저장 동작은 [설정 디자인](./settings.md)의 범위를 유지한다. 이
온보딩에서는 이 단계의 `다음`으로 저장하며, 생략한 선택은 저장하지 않는다.

## 5. 확인과 완료

| 요소        | 문구 또는 표현                |
| ----------- | ----------------------------- |
| 확인 제목   | 이 프로필로<br>시작해 볼까요? |
| 확인 안내   | 입력한 내용을 확인해 주세요.  |
| 다음 action | 다음                          |
| 성공 제목   | 첫 프로필이<br>준비됐어요     |

저장된 Profile의 사진·표시 이름·핸들·소개·Tag·게시 설정을 요약한다. 생략한 미저장 초안과 저장 실패한 값은
요약에 반영하지 않는다. 이름이 비어 있으면 핸들을 표시하며, 빈 소개와 없는 Tag를
채우기 위한 안내를 넣지 않는다. `이전 화면으로 돌아가 바꿀 수 있어요.`, `입력 화면 다시 보기`, 같은 Tag를 쓰는
사람을 만난다는 예고나 홈·핵심 기능을 배운다는 예고는 표시하지 않는다.

최종 완료 화면은 사람 찾기 이후에 표시하며 `시작하기`로 앱 사용을 이어간다. `시작하기` 뒤에는 추가 온보딩을 표시하지 않는다. 입력 단계로 돌아가는 action은 제공하지 않으며, 완료한 뒤의
사진·표시 이름·소개·Tag 수정과 게시 설정 변경은 기존 프로필 편집·설정을 이용한다.
성공 표시 때문에 앱 사용이나 기존 후속 온보딩 진입이 막히는 별도의 막다른 화면을 만들지 않는다.

## 상태·접근성과 기존 화면

- 필드 오류, 이미지 처리 중·실패, 첫 Profile 생성·선택 중·실패와 현재 단계 저장 중·실패를 구분한다. 실패 후에는
  잠금을 풀고 현재 입력으로 재시도할 수 있게 한다.
- 선택 정보의 검증·이미지 처리·저장 실패에도 `지금은 건너뛰기`와 `나중에 설정`으로 저장 없이 진행·완료할 수 있다.
  생략한 정보를 저장 성공처럼 보이게 하지 않는다.
- 첫 단계에서 Profile을 생성했다는 이유로 진행 중인 선택 단계를 닫지 않는다. 흐름을 떠난 뒤 새로 진입한
  Profile 보유자는 기존 선택·사용 흐름으로 이어진다.
- 브라우저·시스템 뒤로가기는 기존 플랫폼 동작을 따르며, 온보딩을 위해 별도의 차단이나 복귀 동작을 추가하지 않는다.
- 입력과 action의 label, 공개 범위의 선택 상태와 설명, 자동 승인 Switch 상태를 접근성 tree에 제공한다.
  선택·오류·disabled 상태를 색만으로 전달하지 않는다.
- Web·iOS·Android에서 같은 단계와 action 의미를 유지하며, 화면 폭·키보드·글자 확대에도 입력과 완료 action이
  가려지지 않게 한다. token과 breakpoint, target은 기존 [접근성 기준](./accessibility.md)과 공용 UI를 따른다.
- 별도의 필수 Coachmark 설명 모드나 `알아보기` action을 새로 만들지 않는다. 공용 Coachmark나 생성 후 핵심
  기능 안내의 별도 이슈 범위를 확장하지 않는다.
- 시안 바깥의 `처음부터 보기`, 폰 프레임, 예시 값, 로컬 완료 처리와 상태 저장 코드는 제품 UI·서버 계약이 아니다.
  생성 후 실제 수정은 위 정책과 현재 사용자 선택을 기준으로 구현한다.

## 구현 후 확인할 결과

1. 첫 화면의 `다음`은 유효한 핸들로 Profile을 생성·선택한 뒤 다음 단계로 이동하고, `나중에 설정`은 생성·선택 후
   곧바로 완료한다. 빈 값·잘못된 값은 생성할 수 없다.
2. 선택 단계의 `다음`은 현재 단계만 저장하고, 생략은 저장 없이 이동한다. 미저장 정보는 확인·완료 요약에
   반영하지 않는다.
3. 공개 범위 세 항목의 설명을 읽고 하나만 선택할 수 있으며, 저장한 값이 확인 화면과 완료 요약에 반영된다.
4. 모든 단계와 완료 화면에 이전 action이 없으며, 완료 후 입력 단계로 돌아가는 동선을 제공하지 않는다.
   지난 정보는 기존 프로필 편집·설정에서 수정할 수 있고, 확인·완료에서 일괄 저장하지 않는다.
5. 선택 정보 오류 후 같은 입력과 같은 Profile로 재시도하거나 저장 없이 생략·완료할 수 있다. 인증·대상 Profile
   전환 뒤의 늦은 결과가 새 대상에 반영되지 않는다.
6. 흐름을 떠난 뒤 새 진입한 Profile 보유자는 기존 선택·사용 흐름으로 이어진다. 기존 프로필 편집·게시 설정·
   Profile 전환과 공개 콘텐츠 읽기에 회귀가 없다.

문서·자동화·Web 결과를 실제 iOS·Android runtime 통과로 일반화하지 않고 검증 결과를 플랫폼별로 기록한다.

프로필 입력과 사람 찾기는 같은 온보딩 화면 틀을 사용한다. 로고·제목·설명·가로 폭·24px 기본 여백과 action 간격을 공유하며, 입력의 5단계 표시는 기존 입력 단계에만 적용한다.
