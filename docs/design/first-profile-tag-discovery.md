# 첫 Profile 태그에서 사람 찾기

## 기준

제품 동작은 [첫 Profile 태그 기반 사람 찾기 정책](../domain/policies/first-profile-tag-discovery.md)과 PROD-1147을 따른다. 기존 [Profile Tag](./profile-tags.md), [관련 Profile 목록](./hashtag-related-profiles.md), [접근성](./accessibility.md)의 표시·상태·입력 기준을 재사용한다.

## 구성

- 저장한 태그를 고르는 영역, 선택한 태그의 관련 Profile 목록, 후속 흐름으로 진행하는 action을 같은 사람 찾기 단계에서 제공한다.
- 태그에는 서버가 반환한 Display Hashtag Name을 표시하고 선택 상태를 색 외의 표현과 접근성 상태로 전달한다. 좁은 화면과 큰 글자에서도 모든 태그를 선택할 수 있게 한다. 태그 개수 상한이나 추천 순서를 새로 만들지 않는다.
- 기존 Profile 목록 행과 개별 팔로우 action을 재사용한다. Profile 열기와 팔로우의 입력 영역을 구분하고 기존 `팔로우`·`팔로잉`·`요청됨` 표현을 유지한다. 본인의 행에서는 기존처럼 자기 팔로우 action을 제공하지 않는다.
- 아무도 팔로우하지 않아도 진행 action을 사용할 수 있다. 팔로우 수를 완료 조건처럼 표시하지 않는다. 세부 제목과 문구는 같은 의미 안에서 다듬을 수 있다.

## 로딩·빈 목록·실패

선택 태그와 목록 상태를 함께 표시한다. 초기 로딩·오류도 어떤 태그를 조회하는지 알 수 있어야 한다. 태그 전환 중 이전 목록을 유지한다면 이전 태그의 결과임을 구분하고 새 태그의 결과처럼 보이지 않게 한다.

이미 확인한 목록과 선택을 유지한 채 실패한 초기 조회나 다음 페이지 조회를 재시도할 수 있게 한다. 목록이 비었거나 오류가 나도 지금은 넘어갈 수 있다. 오류를 빈 목록으로 표시하거나 기존 팔로우·요청 상태를 초기화하지 않는다.

## 플랫폼과 범위

Web·iOS·Android는 같은 정보 구조와 action 의미를 사용한다. 공용 토큰, breakpoint, 플랫폼별 입력 target, focus와 busy·disabled 의미를 유지하며 새 전용 디자인 체계를 만들지 않는다. Web 자동화 결과를 Native runtime 검증 결과로 일반화하지 않는다.

일반 태그 상세 페이지의 기존 뮤트·검색·navigation 기능을 재설계하지 않는다. 이 온보딩은 저장 태그의 사람 찾기와 개별 팔로우에 집중한다. 첫 Profile 입력, 홈 Coachmark와 앱 알림 화면은 각 이슈의 디자인 책임을 유지한다.
