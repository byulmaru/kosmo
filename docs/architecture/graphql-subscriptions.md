# GraphQL subscriptions

GraphQL Yoga sends subscriptions to clients over Server-Sent Events (SSE). Shared event delivery uses Yoga's typed `createPubSub` contract with the process-wide `redisEventTarget` from `@kosmo/core/redis/pubsub`.

Each local consumer creates its typed `createPubSub<Topics>({ eventTarget: redisEventTarget })` instance. The shared module lazily initializes one Redis publisher and one subscriber from `REDIS_URL` on first use; importing it does not connect. If `REDIS_URL` is unset, it does not connect or fall back to localhost. Return each subscription iterator when its consumer finishes to remove that consumer's topic listener. The worker closes the shared connections from its existing `finally` cleanup path.

The worker publishes `homeTimelinePostAdded` to the topic scoped to the recipient Profile after either of the two Home insertion paths creates a new entry. The event payload contains only `postId`. The API exposes a nullable `homeTimelinePostAdded: Post` field, authorizes the subscription at start with the same Member permission used for Home, and uses the operation's selected Profile to choose its topic. For each event, the API clears the cached public Post loader before resolving the current Post, so ordinary current Post visibility and lifecycle checks run; the field can return `null` when the Post cannot be resolved. Event payloads do not carry a Post snapshot or bypass those checks.

The client subscribes to the actual Post and prepends it to the already loaded Home connection; it does not refetch the full Home list for each event. Since Redis delivery can be missed, a latest Home read on app resume or subscription reconnection reconciles gaps. If the reader is below the newest position, the client keeps the reading position and defers lifecycle revalidation until it returns to the top. `새 글 보기` scrolls there immediately without a per-event query; a pending lifecycle revalidation runs after reaching the top.

Redis Pub/Sub is transient, and every GraphQL subscription built on this foundation tolerates event loss. A publish issued while the publisher is disconnected is dropped and is not queued for later delivery. Subscribers reconnect and restore their active topic listeners, but messages published while disconnected are not replayed. The transport does not provide persistence, event IDs, cursors, or replay. The Home timeline reconciles possible gaps with a latest read on app resume or subscription reconnection.

Topic names and payload tuples follow Yoga's `createPubSub` behavior, including dynamic topics encoded as `<topic>:<id>`. Event details cross Redis as JSON, so payloads must be JSON serializable. No-payload events are represented in the serialized envelope without changing their `detail` value.
