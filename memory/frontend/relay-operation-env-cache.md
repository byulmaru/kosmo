# Frontend: Relay Operation, Environment And Cache

Read this entire file when changing Relay documents, actor environments, mutations, normalized state, or connection updates. When writing or modifying React components that use Relay, also use [`relay-best-practices`](../../.codex/skills/relay-best-practices/SKILL.md). Select [`relay-performance`](../../.codex/skills/relay-performance/SKILL.md) for data-fetching, rendering, or cache performance optimization.

## Relay Colocation

- GraphQL query, mutation, fragment document는 실제로 사용하는 `.tsx` 파일에 `graphql` tag로 둔다.
- route는 `useLazyLoadQuery`로 화면 query를 소유하고, GraphQL entity를 소비하는 자식은 자신의 fragment를 선언해 generated `{FragmentName}$key`를 prop으로 받는다.
- 부모는 자식 fragment를 spread하고 fragment ref를 그대로 넘긴다. `id`, `handle`, `displayName` 같은 field subset을 수동 scalar prop으로 복제하지 않는다.
- 한 컴포넌트가 여러 부모 query에서 재사용되더라도 document를 공용 query helper로 빼지 않는다. 재사용 경계는 query가 아니라 fragment다.
- operation name은 화면/컴포넌트 책임을 드러내는 기존 이름을 유지한다. Relay network request body는 `operationName`, persisted text가 아닌 `request.params.text`, `variables`를 포함해 API와 E2E interception 계약을 지킨다.
- generated `__generated__` artifact는 commit하지 않는다. schema 또는 document가 바뀌면 `pnpm --filter @kosmo/app relay`를 실행하고 `check`/build에서도 compiler를 선행한다.
- `DateTime` 같은 custom scalar는 `apps/app/relay.config.json`에서 native-safe TypeScript type으로 매핑한다. DOM 기반 editor type을 scalar boundary에 넣지 않는다.

## Relay Environment And Mutations

- mutation 응답은 영향받는 Node의 `id`와 변경된 필드를 선택해 Relay normalized store를 갱신한다. connection membership는 Relay connection directive를 우선하고, 표현할 수 없는 좁은 변경만 updater로 처리한다. payload가 부족하면 raw `RecordSource`/전역 cache 보정 대신 API 계약을 보완하며, 서버 재판정은 해당 query·connection만 invalidate/refetch한다.
- web request는 same-origin BFF `/graphql`과 HttpOnly cookie를 사용한다. Native request는 channel-configured API `/graphql`에 SecureStore에서 복원한 session token을 Bearer로 보내고 `credentials: 'omit'`을 사용한다. Native AuthSession은 Web과 공유하는 confidential OIDC application의 client ID로 authorization code, PKCE verifier와 exact `kosmo://login/callback` redirect URI만 반환하고, 로그인 화면에 colocate한 Relay `exchangeNativeOidcSession` mutation이 token 없는 native Environment를 통해 같은 API `/graphql`에서 session을 교환한다. API는 server-held client secret으로 code를 교환하며 secret은 Native bundle/request에 포함하지 않는다. BFF REST route, ad hoc GraphQL `fetch`, raw ID/access token 교환을 사용하지 않는다. Native SecureStore 값은 validated API origin, shared OIDC issuer, shared client ID와 token을 함께 저장하며 하나라도 현재 설정과 다르면 삭제해 채널 또는 OIDC application 전환 뒤 이전 bearer를 보내지 않는다. UI code가 web cookie를 직접 읽거나 native token을 URL에 넣지 않는다.
- GraphQL SSE 구독은 query/mutation과 같은 `/graphql` origin, Web cookie 또는 Native Bearer 인증, `selectedProfileId` extension을 사용한다. Relay 표준 disposable로 구독을 dispose하면 해당 operation stream을 닫고, actor Environment 교체나 owner unmount도 같은 Relay lifecycle을 따른다. 클라이언트는 누락된 이벤트를 재생하거나 catch-up하지 않는다. 이벤트 손실 보장은 [GraphQL subscription contract](../../docs/architecture/graphql-subscriptions.md)을 따른다.
- 프로필 actor만 전환하면 Relay Environment와 Store를 새로 만들어 Session과 현재 route query를 새 actor 기준으로 실행한다. 새 actor query가 준비될 때까지 이전 `selectedProfileId`를 숨기되 유효한 Account/Session identity와 auth status를 유지하고, Account-scoped `FeatureFlags` 요청은 프로필 변경으로 다시 시작하거나 무효화하지 않는다. 새 Store에 이전 actor Record를 복사하지 않는다. 준비가 끝나면 shell의 active profile UI는 `currentSession.selectedProfile` 결과에 수렴한다. 이전 actor Store를 재사용하지 않으며, `homeTimeline`과 canonical viewer-relative 상태인 `Profile.viewerState`를 필드 목록으로 invalidate하지 않는다. 관계 mutation의 성공·실패를 이유로 `resetActor()`를 호출하거나 전체 Store를 교체하지 않는다.
- 기억된 Profile 선택값은 Profile ID만 저장하며 Account ID나 Session ID는 함께 저장하지 않는다. 로그인 성공 때마다 이전 선택을 지운다(같은 Account 재로그인도 포함): Native는 새 session token의 SecureStore 저장 성공 후, Web은 로그인 성공 후 provider가 선택값을 복원하기 전에 정리한다. 명시적 로그아웃, 서버에서 확인된 guest/session 만료, Account 변경 관측 때도 지우지만, 프로필 actor 전환, 일반 reload/requery, 일시적인 네트워크 오류만으로는 지우지 않는다.
- 인증 상태 변경은 프로필 reset과 분리한다. Native token 교환/삭제는 SecureStore 저장/삭제 성공 후 auth state를 무효화하고, Web logout 성공 시 이전 Account를 즉시 숨기는 auth invalidation을 수행한다. 오래된 auth/actor 결과는 무시하고 서버가 guest로 확인하면 Account/Session identity를 비운다.
- Relay fetch·refetch·mutation·pending·disposal은 표준 Relay hook, normalized store, declarative directive를 사용한다. 기능 코드는 low-level Environment/Store 조작, mutation commit을 감싼 Promise, 별도 `pending`/`inFlight` 상태로 Relay lifecycle을 재구현하지 않는다. mutation document와 `useMutation`은 mutation을 실행하는 실제 action owner에 colocate하고 `useMutation`의 in-flight 상태를 사용한다. 표준 Relay API로 표현할 수 없는 좁은 membership updater와 actor Environment provider boundary만 예외로 한다. membership updater는 이미 로드된 기존 real-Post connection 또는 이미 로드된 Profile record의 인자 없는 `postRequests` 목록에만 적용하고, raw `RecordSource`나 전역 Store/cache 조작으로 범위를 넓히지 않는다. actor 변경·요청 실패·접근성 계약은 각자의 소유자가 보존한다.
- 게시 연결 갱신은 producer별로 별도 처리한다. 모든 local `createPost` mutation은 같은 PostRequest 경로를 사용하며, `CreatePostInput`은 `requestId`를 받지 않고 각 요청 ID는 서버가 생성한다. 따라서 오류 뒤 수동 재제출도 이전 요청을 재생하지 않는 새 요청이다. 새 요청은 Media가 없거나 모두 READY면 publication을 기다려 `PUBLISHED` request를 반환하고, 유효한 Local UPLOADING Media가 있으면 즉시 request acknowledgement를 반환한 뒤 처리를 계속한다. 결과 필드 선택은 admission을 바꾸지 않는다. `CreatePostPayload.post`는 nullable이며, 이 응답에서 반환된 request 상태가 `PUBLISHED`일 때만 Post를 조회하고, UPLOADING Media의 즉시 acknowledgement에서는 `null`을 반환한다. 이 projection은 Workflow를 다시 기다리거나 조회하지 않는다. `request`는 nullable이며 공개 shape은 [PostRequest 계약](../../docs/domain/objects/post.md)을 따른다. 전체 제출 snapshot은 Temporal Workflow 안에 게시 처리와 내부 멱등 처리를 위해 유지하며 Composer에 재노출하지 않는다. `FAILED` 카드의 새 글 작성은 현재 선택 Profile의 일반 Post Composer를 열되 요청 snapshot을 복사하지 않는다. 기존 일반 draft는 일반 Composer 정책을 따르며, 로컬 draft가 없을 때만 새 입력이 비어 있다. 접수 ACK는 이미 로드된 작성 Profile의 인자 없는 `postRequests` 목록에 `PUBLISHED`가 아닌 경우 한 번 추가한다. `Profile.postRequests`는 Account 소유의 보존된 비공개 요청 중 `PUBLISHED`가 아닌 상태를 모두 반환한다. Home의 optional request-card region은 `node(id: $profileId)`의 Profile fragment를 사용하며, 별도 request route나 root `postRequest`·`postRequests` query, statuses 인자는 없다. Home은 `QUEUED`, `PROCESSING`, `PUBLISHING`, `CONFIRMING`, `FAILED`와 transient `PUBLISHED` settlement만 표시하고 `CANCELLED`는 숨긴다. 목록은 flat 배열이며 client page token, Relay connection, cursor 누적은 사용하지 않는다. Post List 후보나 정책 필드를 클라이언트에서 합성하지 않는다.
- 앱의 미디어 입력은 AI 필터 필드 이름으로 `applyAiProhibitFilter`만 사용하며, 생략하면 false다.
- `createPost` 첫 응답에서 이미 `PUBLISHED`인 요청과 이후 `PUBLISHED`로 전이된 요청 모두 surface가 닫히기 전에 결과를 반영한다. 표준 Relay `commitLocalUpdate`와 `ConnectionHandler`로 서버가 반환한 실제 Post를 해당 응답의 Author 및 현재 Relay Environment가 현재 actor와 일치할 때만 이미 로드된 그 actor의 Home connection에 추가하고 중복을 제거한다. Published request는 이미 로드된 Profile의 `postRequests` 목록에서 제거한다. 목록의 초기 응답에는 `PUBLISHED` 이력이 없으므로, 목록 로드시 Home Post를 재생성하지 않는다. 합성 edge·cursor·정책 필드, 전역 Store 복사, 닫힌 이력의 Home prepend는 하지 않는다. `CANCELLED`는 Profile의 보존된 `postRequests` 응답에 남되 Home request-card region의 eligible 상태 필터에서 제외되며, Home의 별도 요청 캐시는 없다. `Profile.postRequests`는 현재 선택한 Profile의 역할이 `Member` 이상인 Account가 읽을 수 있고, 조회한 Profile에 속하며 해당 Account가 소유한 요청만 반환한다. 요청 안의 Post는 일반 Post visibility 규칙을 따른다. actor reset은 A에서 B로 요청이나 Post record를 복사하지 않는다.
- 프로필 선택이 성공하면 응답의 `selectProfile.profile.id`를 actor reset input으로 사용하고 새 actor query가 준비되면 UI를 갱신한다. mutation payload의 부분 `Session.selectedProfile`을 이전 actor Store에 게시하지 않으며, GraphQL 오류 응답이나 network 오류에서는 actor reset을 시작하지 않고 기존 picker 오류 계약을 유지한다.
- Route와 독립 surface의 GraphQL/network 오류는 가장 가까운 error boundary가 소유하고, 해당 query만 새 `fetchKey` 또는 query reference로 재시도한다. 루트까지 전파된 오류는 특정 query를 추측해 재시도하지 않고 Relay·Session provider runtime 전체를 다시 생성한다. backend `message` 원문 노출 정책이 확정되지 않은 흐름에서는 컴포넌트마다 ad hoc 분기를 만들지 않는다.

## Relay Connections

- followers/following처럼 다음 페이지가 필요한 fragment는 `@argumentDefinitions`, `@refetchable`, `@connection`을 선언하고 `usePaginationFragment`로 읽는다.
- route state에서 edge를 수동 concat하거나 cursor 중복 제거 helper를 만들지 않는다. Relay connection identity와 `loadNext`가 누적을 소유한다.
- 다음 페이지 로딩 중에는 중복 요청을 막고, 실패해도 기존 edge를 유지하며 같은 위치에서 재시도할 수 있게 한다. `hasNext`가 false면 load-more action을 숨긴다.
- connection key는 component와 관계가 드러나는 안정적인 이름을 사용한다. filter argument가 생기면 `filters`를 명시해 서로 다른 목록이 같은 connection으로 합쳐지지 않게 한다.
- `Profile.postRequests`는 retained 상태 중 `PUBLISHED`를 제외한 요청을 flat argumentless array로 반환한다. 응답은 `node(id: $profileId)`의 Profile inline fragment로 읽고, cache 갱신은 이미 로드된 동일 Profile record의 `postRequests` field만 수정한다. Home request-card region은 eligible 상태만 로컬에서 표시하고 transient `PUBLISHED` settlement를 반영하되 `CANCELLED`는 전체 Profile 요청 이력에 남긴다. 다른 목록에서 필요한 페이지네이션은 기존 Relay connection pattern을 따른다.
