## Current Constraints

- 현재 전달물은 행사에서 자연어 뮤트 구상을 설명할 HTML 목업 또는 이미지다. 앱 안에서 동작하는 기능을 만드는 작업이 아니다.
- `apps/app/src/theme/tokens.ts`에 KOSMO의 semantic color와 font family가 있다. 시각 기준은 `docs/design/colors.md`, `docs/design/foundations.md`, `docs/design/typography.md`에서 확인했다.
- 기존 Word Mute Rule은 단어, Hashtag Mute Rule은 Hashtag, Profile Mute는 Profile을 기준으로 노출을 제어한다. 이 소개 자료는 어느 정책도 수정하지 않는다.
- 행사 기기와 화면 비율은 아직 지정되지 않았다. 다음 제작 세션에서 실제로 확인한 표시 크기를 기록한다.

## Practical Approach

다음은 제작을 위한 작업 제안이다. 장면 수, 예문, 파일 위치는 소개 목적을 유지하는 범위에서 바꿀 수 있다.

### 전달물

정적 HTML 한 파일을 기본안으로 삼는다. 제안 경로는 `docs/demos/natural-language-mute/index.html`이다. 화면을 바로 열어 소개하고, 필요하면 같은 화면을 이미지로 활용한다. HTML과 이미지 모두를 의무 전달물로 요구하지 않는다.

기존 앱의 route, Relay, API와 Storybook에 연결하지 않는다. 앱의 공용 컴포넌트나 새 패키지를 추가하는 대신 소개 자료에 필요한 표시만 구성한다. 제작에 필요한 기존 폰트와 자산은 현재 저장소에서 확인하고, 별도 의존성이나 빌드 체계를 선행 도입하지 않는다.

### 화면 흐름

| 장면        | 보여줄 내용                                                                   | 방문자가 이해할 점          |
| ----------- | ----------------------------------------------------------------------------- | --------------------------- |
| 입력 예시   | “보고 싶지 않은 내용을 문장으로 적어보세요”와 예문, 적용 동작을 나타내는 표시 | 무엇을 입력할 수 있는지     |
| 적용된 조건 | 방금 제시한 문장을 읽기 쉬운 조건으로 다시 표시                               | 어떤 조건으로 피드를 보는지 |
| 피드 결과   | 같은 예시 피드의 적용 전·후. 대상 글은 가림 표시로 바꾸고 관계없는 글은 유지  | 어떤 글이 가려지는지        |

입력란과 적용 표시는 준비한 화면이다. 타이핑, 추론, 비동기 대기, 오류·재시도와 영속 저장을 구현할 필요는 없다. 추가 조작 없이도 세 장면의 연결을 읽을 수 있도록 배치한다.

### 대표 시나리오 초안

- 입력 예문: “아직 보지 않은 작품의 결말이나 반전 이야기는 보고 싶지 않아요.”
- 가림 대상 예시: 가상의 작품 결말이나 반전을 직접 설명하는 글.
- 유지할 예시: 결말을 언급하지 않는 작화 감상, 행사 준비와 일상 글.
- 결과 화면에서는 대상 글의 자리에 “설정한 조건으로 가려진 예시 글”처럼 상태를 드러내는 문구를 둔다.

전·후 피드의 글과 순서를 맞춰 문장과 결과를 쉽게 비교하게 한다. 위 예시는 설명을 위해 만든 모의 결과이며, 자연어 해석 규칙이나 모델의 지원 범위를 정의하지 않는다.

### 시각 방향

KOSMO의 Yellow primary, 밝은 canvas, 중립 foreground와 border를 기본으로 한다. UI는 SUIT, 예시 글은 Pretendard 계열을 기준으로 잡고 한글이 실제로 표시되는지 확인한다. 입력 예문과 가림 상태를 색만으로 구분하지 않고 문구와 함께 표시한다.

화면의 짧은 안내는 “자연어 뮤트 구상을 설명하기 위한 예시 화면입니다” 정도로 제안한다. 방문자 안내에 내부 모델 이름이나 기술 구조를 설명할 필요는 없다.

## Alternatives and Traps

- 이미지 몇 장으로만 구성해도 현재 완료 기준을 만족한다. 수정과 전·후 비교가 쉬운 HTML을 기본 제작안으로 제안한다.
- 동작하는 체험 앱은 입력 처리, 예외와 시연 환경을 더 정해야 한다. 현재 전달에는 필요하지 않다.
- mock 성공을 실제 모델의 정확도나 프로덕션 검증 결과로 표현하지 않는다.

## Risks / Limits

HTML을 1440×1080과 390×844 viewport에서 직접 확인했다. 실제 행사 기기와 이미지·인쇄 품질은 검증하지 않았다. 폰트 미설치 기기는 시스템 한글 sans-serif로 표시한다. 실제 모델·계정 설정·Native 앱 동작을 검증했다는 주장은 하지 않는다.

## Open Questions

현재 세션에 남은 미결정 사항은 없다. 행사 표시 기기와 예문 세부사항은 자료 제작을 막는 제품 결정이 아니며, 현재 범위 안에서 조정할 수 있다.
