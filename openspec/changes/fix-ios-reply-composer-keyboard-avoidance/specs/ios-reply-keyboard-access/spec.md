## ADDED Requirements

### Requirement: iOS 답글의 키보드 표시 중 작성 도구 접근

iOS 답글 작성기는 소프트 키보드가 열린 동안 이미지 첨부·CW 버튼과 남은 글자 수를 보이고 해당 버튼을 조작할 수 있게 해야 한다 (SHALL).

**Source Context:** PROD-1080의 범위와 완료 기준. 아래 내용은 기존 요구사항의 세션 검증 메모다.

#### Scenario: 본문 입력과 작성 도구 사용

- **WHEN** iOS 답글의 본문에 포커스해 소프트 키보드를 연다.
- **THEN** 이미지 첨부·CW 버튼과 글자 수가 키보드에 가려지지 않는다.
- **AND** 이미지 첨부와 CW 조작을 실행할 수 있다.

#### Scenario: 공간이 부족한 작성 상태

- **WHEN** 이미지·CW 또는 긴 본문으로 작성 내용이 키보드 위 공간을 넘는다.
- **THEN** 필요한 본문·첨부 내용을 스크롤해 볼 수 있고 현재 입력 위치와 작성 액션에 접근할 수 있다.

### Requirement: 키보드 전환과 기존 작성 흐름 보존

키보드 표시·해제·재진입에서 footer 겹침이나 과도한 빈 공간이 없어야 하며 기존 초안·첨부·CW·답글 제출 흐름을 보존해야 한다 (SHALL).

**Source Context:** PROD-1080 완료 기준, `docs/design/post-composer.md`의 lifecycle과 Native 검증 계약.

#### Scenario: 키보드 반복 전환

- **WHEN** 같은 답글에서 키보드를 닫았다 다시 열고 입력을 계속한다.
- **THEN** safe area와 footer 위치가 복원되며 작성 내용이 유지된다.
- **AND** footer 겹침이나 과도한 빈 공간이 생기지 않는다.

#### Scenario: 첨부와 CW를 포함한 제출

- **WHEN** 이미지 첨부·제거와 CW 설정을 한 뒤 유효한 답글을 제출한다.
- **THEN** 기존 답글 제출 흐름이 유지되고 실패 시 초안과 재시도 경로를 보존한다.

#### Scenario: 공용 경계의 회귀 확인

- **WHEN** 수정 후 일반 작성기와 같은 surface의 인용 작성기에서 키보드와 작성 도구를 사용한다.
- **THEN** 기존 작성 동작과 일반 작성기의 키보드 회피가 유지된다.
